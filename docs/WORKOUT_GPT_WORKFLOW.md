# Motion Log — 운동 프로젝트 처리 규칙

Motion Log의 운동 입력은 웹사이트에서 이미지를 직접 업로드하는 방식으로 처리하지 않는다.

## 사용 흐름

1. Galaxy Watch에서 운동을 완료한다.
2. Samsung Health에서 운동 상세 화면을 캡처한다.
3. 필요하면 지도/그래프 화면과 랩 화면을 추가로 캡처한다.
4. ChatGPT의 `프로젝트 → 운동` 대화에 캡처를 올린다.
5. 운동 기록을 추출하고, 확인 가능한 값만 데이터로 사용한다.
6. 기존 Motion Log 기록과 비교해 당일 운동을 분석한다.
7. 사용자가 확인한 기록을 Motion Log의 GitHub 데이터셋에 추가한다.
8. Vercel이 배포된 이후 웹에서 누적 기록과 분석을 확인한다.

## 기본 입력 화면

- 운동 상세: 날짜, 운동 종류, 거리, 시간, 페이스, 심박, 케이던스, 칼로리 등
- 지도/그래프: 경로, 페이스 변화, 심박 변화, 고도 등
- 랩: 구간별 기록이 필요할 때만 사용

## GitHub 데이터셋

현재 운동 데이터의 기준 파일은 `public/motion-log-data-test.json`이다.

새 운동을 반영할 때는 기존 배열을 유지하면서 새 기록 객체를 추가한다.

- 기존 `id`는 변경하지 않는다.
- 새 기록은 고유한 `id`를 사용한다.
- 동일 운동을 중복 추가하지 않는다.
- 날짜 형식은 `YYYY-MM-DD`를 사용한다.
- 운동 종류는 현재 웹앱이 사용하는 `러닝`, `걷기`, `자전거`, `등산`, `수영`, `기타` 중 하나를 사용한다.
- 숫자 값은 Samsung Health 화면에서 확인된 값만 기록한다.
- 표시되지 않은 값은 임의 추정하지 않고 생략한다.
- 캡처에 원본 수치가 보이지 않는 항목은 JSON에 만들지 않는다.
- 새 기록을 추가한 뒤 웹앱의 `GitHub 데이터 동기화`에서 새 기록이 보이는지 확인한다.

## 분석 원칙

운동 분석은 숫자 나열이 아니라 기존 기록과의 변화에 초점을 둔다.

가능한 범위에서 다음을 비교한다.

- 거리와 운동 시간
- 평균/최고 페이스 및 속도
- 평균/최대 심박
- 평균/최대 케이던스
- 고도 상승/하강
- VO₂ Max
- 같은 기간의 이전 운동과의 변화

의미 있는 비교가 어려운 항목은 억지로 결론을 만들지 않는다.

## GPT 응답 권장 형식

사진을 받은 뒤 다음 순서로 정리한다.

### 1. 추출 데이터

확인된 값만 항목별로 정리한다. 보이지 않는 값은 `미표시`로 구분하고 저장 데이터에서는 생략한다.

### 2. 운동 분석

이번 운동의 핵심 특징과 이전 기록 대비 변화를 설명한다. 단순한 최고/최저 기록보다 페이스·심박·케이던스·고도와 거리의 관계를 우선 본다.

### 3. 저장 전 확인

- 날짜
- 운동 종류
- 거리
- 운동 시간
- 동일 기록 여부
- 새 `id`

을 확인한다.

### 4. 저장

사용자 확인이 끝난 뒤에만 `public/motion-log-data-test.json`에 새 기록을 추가한다. 기존 기록은 그대로 유지한다.

## 웹사이트 역할

Motion Log 웹앱은 운동 캡처를 분석하는 입력창이 아니라, GitHub에 저장된 운동 기록을 조회·분석·백업하는 개인 운동 아카이브로 사용한다.
