# Motion Log Next 설계 기준

## 1. 목표

Motion Log는 운동 사진을 웹앱에서 직접 OCR 처리하는 서비스가 아니라, 다음 흐름을 유지한다.

Galaxy Watch → Samsung Health → 캡처 → ChatGPT 운동 프로젝트에서 판독·검증 → GitHub 데이터셋 → Motion Log 시각화

웹앱에는 Vision/OCR API를 추가하지 않는다. 입력 파이프라인을 단순하게 유지하고, 운동 데이터의 정확성과 장기 누적성을 우선한다.

## 2. 데이터 계층

### 운동 데이터

`public/motion-log-data-test.json`에 저장되는 운동 기록이 기준 데이터다.

기록은 기존 ID를 유지하고, 새 기록에는 고유 ID를 사용한다. 스크린샷에 실제로 보이는 값만 저장하며 보이지 않는 값은 추정하지 않는다.

### 앱 설정

운동 데이터와 별도로 브라우저 로컬 저장소에 관리한다.

- 테마
- 향후 추가될 개인화 설정

### 로컬 캐시

브라우저에서는 운동 데이터를 `localStorage`에 캐시하고 GitHub 데이터와 ID 기준으로 병합한다. 로컬에서 휴지통으로 이동한 기록과 메모는 원격 동기화 시 보존한다.

## 3. 대시보드

### 기본 요약

대시보드는 최근 운동, 주간 운동/거리, 연간 거리, 누적 거리, 최장 러닝, 연속 운동을 우선 표시한다.

### 운동 스냅샷

실제로 사용하는 종목인 `러닝`, `등산`만 대시보드 스냅샷으로 제공한다.

러닝에서는 페이스, 속도, 심박, 케이던스, VO₂ Max 등을 중심으로 표시하고, 등산에서는 거리, 누적 상승/하강고도, 심박, 칼로리 등을 중심으로 표시한다.

데이터가 존재하지 않는 지표는 `—`로 표시하고 임의의 값을 생성하지 않는다.

### 월별 거리 / 캘린더

현재 연도의 월별 거리와 월간 운동 캘린더를 제공한다. 캘린더 날짜를 누르면 해당 날짜의 운동 기록으로 이동한다.

연간 운동 히트맵과 연간 거리 목표 기능은 현재 사용성 기준으로 제외한다.

## 4. 기존 기능 유지

다음 기능은 기존 UX를 유지하면서 확장한다.

- 운동 기록 검색/정렬/종목 필터
- 기간 분석 및 직접 기간 지정
- 캘린더 날짜 이동
- 운동 상세 모달
- 휴지통/복원/영구 삭제
- GitHub 데이터 동기화
- JSON 백업/복원
- CSV 내보내기
- 라이트/다크 테마

## 5. 입력 규칙

ChatGPT 운동 프로젝트에서 운동 캡처를 처리할 때 다음 규칙을 고정한다.

1. 날짜는 `YYYY-MM-DD`로 통일한다.
2. 운동 종류는 `러닝`, `걷기`, `자전거`, `등산`, `수영`, `기타` 중 하나를 사용한다.
3. 기존 기록과 중복되는 기록은 새로 만들지 않는다.
4. 기존 ID는 변경하지 않는다.
5. 새로운 기록은 고유 ID를 만든다.
6. 스크린샷에 보이지 않는 수치를 추정하거나 만들어내지 않는다.
7. 저장 데이터의 Key와 단위는 Motion Log 스키마에 맞춘다.
8. 기록을 저장하기 전에 추출값과 기존 기록의 중복 여부를 확인한다.

## 6. 향후 추가 기능 우선순위

1. PWA / 홈 화면 설치 경험
2. 오프라인 조회 및 캐시 안정성 강화
3. 운동 기록 공유 카드
4. 필요성이 확인된 추가 통계

사진 업로드, Tesseract.js, 외부 Vision/OCR API, 별도 서버 DB, 로그인 시스템은 현재 범위에서 제외한다.

## 7. 배포 원칙

작업은 `motion-log-next`에서 진행한다.

1. 코드 변경
2. 로컬 `npm.cmd run build`
3. 로컬 화면 검수
4. 데이터 동기화/백업/필터/캘린더/러닝·등산 스냅샷 검수
5. 이상 없을 때만 `main` 병합
6. 최종 확인 후 Vercel Production 배포

Vercel 배포는 개발 중간 단계에서 반복하지 않고 마지막 단계에서 1회 진행한다.
